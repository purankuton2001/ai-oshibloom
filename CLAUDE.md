# CLAUDE.md

Working rules for AI OshiBloom. They apply to AI coding agents (Claude Code, Codex and others; `AGENTS.md` points here) and to humans alike.

## This repository is public

Everything pushed here is visible to anyone, forever: file contents, commit messages, author names and emails. History was rewritten once (2026-09-07) to remove a personal email address, the name of an unpublished project and tool session links. We do not want to do that again. The rules below are enforced by `scripts/check-public-hygiene.sh`, which runs as a git hook (installed by `npm ci`) and in CI.

### Commits

- Author and committer email must be a GitHub noreply address (`<id>+<login>@users.noreply.github.com`) or a tool's noreply address. Never a personal mailbox. Check `git config user.email` before the first commit and set it for this repository if needed.
- The message describes the change. The only allowed trailer is `Co-Authored-By`. Do not add session links, run IDs or any other tracking trailer, even if your tooling asks for one.
- Do not mention private repositories, this project's former working name or other unpublished projects. The blocked list lives in `scripts/check-public-hygiene.sh`; extend it when a new private name appears.

### Files

- Never commit `.env`, keys, tokens, service-account files or anything matching the secret patterns in the hygiene script. Configuration is documented in `.env.example` with empty values.
- `data/` (runtime personas, clips, logs) and `local/workflow.json` are ignored. Keep them that way.
- New media (image, video, audio) needs an entry in `docs/ASSETS.md`: what it shows, how it was made (tool, date, prompt) and that it is original. No real people, no existing characters, no third-party IP. Media under `docs/media/` is documentation only and outside the MIT grant.

### Documentation

- Write for someone outside the project. No working logs ("the user asked…", "following the request…"), no account state (balances, key rotation), no local paths under `data/`, no internal project names.
- A verification record has three parts: setup, measurements with their conditions, and what was not covered. `docs/LIVE-TEST.md` is the template.

### Before you push

```bash
npm run build && npm test && npm run hygiene
```

The hygiene check scans every commit reachable from `HEAD` and every tracked file. If it fails, fix the commit locally (`git commit --amend`, or `git rebase -i` for an older one) before pushing. Once a bad commit is on GitHub it is part of the public record.

## Project shape

- `src/domain.ts` types and settings, `src/engine.ts` comment queue and playback, `src/providers.ts` fal/OpenAI adapters, `src/director.ts` continuous-live (WebRTC) mode, `src/guard.ts` own-character safety guard, `src/youtube.ts` live-chat polling, `src/server.ts` the single HTTP/WebSocket server bound to `127.0.0.1`.
- `public/` is the studio UI; `public/director-client.js` is generated by `npm run build` from `scripts/build-client.mjs`.
- `test/` runs with `npm test` (Node's test runner, no keys needed).
- The safety rule that keeps the project shippable: nothing may let a real person's face or voice, or an existing character, into the pipeline. Changes to `src/guard.ts`, `src/providers.ts`, `src/director.ts` and `src/youtube.ts` need a maintainer's approval (`.github/CODEOWNERS`).
- See `CONTRIBUTING.md` for the development loop and review process, `docs/SETUP.md` for real-generation setup and costs.

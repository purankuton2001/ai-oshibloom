# fal live verification — 2026-09-05

Measurements from real fal.ai generation runs against this app on 2026-09-05, recorded so the numbers in the README have a source. All runs used a fal key from a local `.env` (never committed). Small, uncontrolled samples: treat every figure as one observation, not a guarantee.

## Setup

- Persona: **Yui Live**, an original adult anime character (see [ASSETS.md](ASSETS.md#readme-demonstration-media) for provenance). One face plus two derived reference views generated in-app.
- Text replies: OpenAI was not configured, so reply text is the demo preset. Speech and video were genuinely generated by fal after the browser Send click.
- Automated tests and the production build passed before and after the runs.

## Standard reference route (MiniMax H3 Max, reference-to-video)

| Step | Result |
|---|---|
| Anime face generation | 5.93 s end to end |
| Preset synthetic TTS | MP3, 6.43 s |
| Idle clip / reaction clip | H.264 832×480, 5.17 s, AAC audio |
| Reaction prompt | "Smile and wave hello to everyone." — sampled frame shows smile and raised hand |
| Comment received → reaction downloaded (first trial) | 16.81 s (above the 15 s target) |
| Comment received → browser playback (second trial, recorded) | 9.70 s (video ready at 9.68 s) |
| In-app budget estimate, all calls | $1.08 (first session), $2.08 cumulative after the recorded run |

Recorded run details: comment `手を振って、笑顔で挨拶して！`, selected 11:17:28.379Z, video ready 11:17:38.058Z, playback acknowledged 11:17:38.079Z, playback ended 11:17:43.317Z. Playback and the return to idle were verified from read-only browser video state (`readyState=4`, visible, playing). The character kept the brown bob, cream cardigan and clover accessory in the reaction; this is a visual spot-check, not an identity guarantee.

The screen recording (~21.8 s, 1280×720) is built from 100 real browser captures at their original timestamps, encoded at 30 fps with duplicated frames. No speed-up and no fabricated UI states. `?record=1` selects a compact studio layout so the stage and chat input fit one 1280×720 capture.

## Turbo route (MiniMax H3 Max Turbo, native audio)

`videoMode: turbo` uses `minimax/h3-max-turbo/image-to-video` with the selected face as first frame, 480p, 5 s. Speech and mouth motion are generated in the same video from a fixed Japanese adult idol voice description. Turbo's published schema has no audio-reference input, so this is voice prompting, not a fixed voice identity; the standard reference route keeps audio-reference support. Three-second output is unsupported (schema minimum is 5 s).

| Measurement | Result |
|---|---|
| Comment → browser playback, two single trials | 7,485 ms and 6,596 ms |
| Comment → playback, after engine prefetch change | 6,000 ms |
| Two-comment run: first playback | 8,598 ms after its comment |
| Two-comment run: second playback | 5,490 ms after its comment (submitted during first playback) |
| Gap between first clip end and second clip start | 268 ms |

Output clips contain H.264 video and non-silent AAC audio; browser media state confirmed `muted=false` during playback. Japanese pronunciation and voice preference were not assessed by listening.

The engine generates the next accepted comment while the current clip plays, buffering at most one completed clip. This overlaps generation and playback; it does not stream incomplete clips or guarantee uninterrupted playback. Tests cover ordering, cancellation and prefetched-generation failure without interrupting current playback.

## Voice Design

Voice Design succeeded on a later attempt (an earlier call returned 403). The persona stores a persistent synthetic voice ID and a 7.04 s Japanese reference MP3. The standard reference route used it with the three identity images and produced an audio-video clip with playback at 14,810 ms. Speaker similarity was not evaluated by listening or speaker embedding. Turbo has no reference-audio input and keeps using the fixed voice description.
